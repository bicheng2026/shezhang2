〇、先说清楚这是个什么东西

一句话：一座你们班自己的教材库，加一个会自己查书的 AI Agent。

分三块，可以只做第一块：

块是什么必须吗
① 文库站网页版教材库 + AI 问答必须，本指南主讲
② 公告聚合自动抓学校官网通知，做成待办清单可选
③ 群消息收录把群里值得留意的通知收进来可选，且必须守住隐私红线

⚠️ 最重要的一点：这是一个 Agent，不是普通问答机器人。

同学提问后，它会自己决定去查哪几本书、要不要再查一轮，然后带着出处回答。

所以你会看到它「先动几下才回答」——那是在翻书。

一、你要准备什么

三样，全部免费：

要什么干什么用去哪弄
GitHub 账号代码和资料放这，Pages 免费托管网页github.com 注册
AI 接口的 API Key让 AI 能回答问题（每位同学各填各的）见第二节
电脑（Windows 即可）往仓库传资料时用—

不需要：服务器、域名、备案、数据库、任何付费服务。

二、AI 从哪来（关键，务必读懂）

这一站本身不含任何 API Key。 这是刻意设计的：

  • Key 由每位使用者自己在浏览器里填，存在自己电脑上，不上传、不进仓库
  • 站长不用替全班出钱，也不承担保管义务

推荐两家（都有免费额度）：

平台接口地址填什么模型名填什么备注
DeepSeekhttps://api.deepseek.com/v1deepseek-chat新号常送额度，便宜
硅基流动https://api.siliconflow.cn/v1Qwen/Qwen2.5-7B-Instruct有若干免费模型

怎么拿到 Key：注册平台 → 找到「API Keys」→ 新建 → 复制那串 sk-…。

同学怎么填：打开网站 → 右上角 设置 → 填三格（接口地址 / API Key / 模型名）→ 保存 → 回对话页提问。

不填也能用：文库能翻、公告能看，只是问 AI 不会回答。

三、十分钟搭好最小可用版

Step 1 · 建仓库

  1. 登录 GitHub，点右上角 + → New repository
  2. 名字随意，比如 class-library
  3. 勾 Public（私有仓库的 Pages 要收费）
  4. 点 Create repository

Step 2 · 把这一套文件传上去

把上一任站长给你的整套目录传进仓库。命令行方式（在项目目录里执行）：


git init
git add .
git commit -m "init"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
如果 git push 老是失败（学校网常见），可以改用 GitHub 网页版「Add file → Upload files」手动传；
文件多的话建议分批传，别一次拖几百兆。

Step 3 · 开启网页托管（Pages）

  1. 仓库页 → Settings → 左侧 Pages
  2. Source 选 Deploy from a branch
  3. Branch 选 main / 目录选 / (root) → Save
  4. 等 1–3 分钟，访问 https://<你的用户名>.github.io/<仓库名>/

能打开登录页 = 成功。

Step 4 · 设访问口令（建议）

配置文件是 网页版/data/access.json：


{
  "lock": true,
  "salt": "自己换一串随机字符",
  "admin": "管理员密码的哈希值",
  "user": "",
  "temp": false,
  "issuedAt": 0,
  "until": 0
}
  • lock: true = 需要口令才能进；false = 任何人可进
  • admin 存的是哈希，不是明文：SHA-256(salt + "::" + 你的密码)，可用下面这段算：

import hashlib
salt = "换成你 access.json 里的 salt"
pw   = "你想用的管理员密码"
print(hashlib.sha256((salt + "::" + pw).encode()).hexdigest())

把输出填进 admin，明文自己记好（别写进仓库）。

  • 进后台：网页上按 Ctrl + Shift + A，输管理员密码

Step 5 · 让同学能提问

把第二节的「怎么填 Key」发到班群。完事。

三·B、接机器人？**请部署你自己的云函数**

一句话：你的机器人走你的云函数，别蹭别人的。
群消息是班级隐私，从头到尾不该经过别人的服务器 —— 技术上虽然能共用， 但「各用各的」才是干净做法。

网页本身不需要云函数也能跑（看文库、问 AI 都行）。 只有「把班群消息自动收进来」这一件事需要它。要做，就照下面走。

B1 · 下载部署包

📦 点这里下载「云函数部署包.zip」 （含 scf_bootstrap / server.js / handler.js 和一份《部署说明.md》）

B2 · 传到腾讯云（约 10 分钟）

  1. 打开 console.cloud.tencent.com/scf →「函数」→「新建」
  2. 函数类型必须选「Web 函数」（选成事件函数收不到消息），运行环境 Nodejs16.13
  3. 上传刚下载的 zip（根目录直接是那三个文件，别套文件夹）
  4. 建好后到「函数配置 → 环境变量」，填：GH_TOKEN、GH_REPO_QQ（你的私有库）、 PUBLIC_BASE（你函数地址，下一步拿到）
  5. 到「触发器」抄下你的函数网址，回填 PUBLIC_BASE

完整细节在包里的《部署说明.md》，照着做就行。

B3 · 网页上认这台函数

  1. 打开你的文库网页 →「设置」→「我的云函数」，填你函数地址 →「保存并测试」
  2. 显示「✓ 探通了」即成功
  3. 往下「我的机器人」贴 AppID + AppSecret → 点「接入」→ 拿到一段回调地址
  4. 把那段回调地址填到 q.qq.com 的「消息推送 / Webhook」，保存
全程 没有口令：贴 AppID + AppSecret 就通。数据按你的 AppID 分文件存在你自己的私有库里， 别人读不到，你也读不到别人的。
想让全站都默认用你这台（而不是只有你这台设备）？ 在站点根目录放一个 data/cloud.json： 
{ "cloud": "https://你的函数地址" }
没这个文件时，页面用本站原来的默认函数 —— 所以不填也不会坏。

四、把资料收进文库（入库）

4.1 先理解结构


网页版/lib/             ← 正文（markdown）
  ├─ 00_待入库/
  ├─ 01_教材/           ← 侧边栏只列这里的
  ├─ 02_课件题库/
  ├─ 03_学科/
  └─ 04_校务公开/
网页版/data/index.json  ← 索引（章节标题 + 字节偏移），由脚本生成
网页版/data/crypto.json ← 加密标记（有这个文件就说明 lib 是密文）

索引只认 .md。 PDF / PPT / Word 要先转成 markdown。

4.2 入库三步


# ① 如果 lib 已经是密文，先还原成明文（复制 data/crypto.json 在就说明是密文）
python web/decrypt_all.py

# ② 把资料转成 md 放进 lib/<分类>/（转换用 web/extract.py，支持 PDF/PPT/DOCX/图片）

# ③ 重建索引 → 重新加密
python web/build_index.py
python web/encrypt_all.py

markdown 格式要求（影响能不能被搜到）：


# 书名                        ← 第一个 # 是书名

## 第一章 绪论                 ← ## 是章节标题，索引按它切
正文…

## 第二章 …
  • 没有 ## 的文档，整篇算一章（不会丢）
  • 偏移量按 UTF-8 字节算，中文一个字 3 字节——别手工改，交给脚本

4.3 加密是怎么回事（可选但建议）

encrypt_all.py 会把 lib/*.md 和 index.json 原地加密（AES-256-CTR，密文与明文等长）。

这样公开仓库上只放着密文，别人拿到文件也读不出内容。

  • 密钥来自 web/sz_crypto.py 里的口令+盐 —— 改成你们自己的
  • 加密后 data/crypto.json 会出现，是「已加密」标记
  • 下次改资料前必须先 decrypt_all.py，否则新内容会混进密文里

4.4 推上去


cd 网页版
node deploy.mjs index.html data/index.json     # 只推指定文件
本项目自带的 deploy.mjs 走 GitHub API 直传，不依赖 git push，
对付校园网不稳特别管用。首次用前把里面的 REPO 改成你的仓库。

五、（进阶）想直接看原版 PDF 带插图？

markdown 只有文字，图全丢了。想看原版 PDF 有个现实问题：

PDF 很大，塞不进主仓库。 举例：50 册教材原本 3.6 GB，而：

限制上限
GitHub 单文件100 MB（超了直接拒收）
仓库 / Pages 站点1 GB 软限（超了可能构建失败）

两个可行做法：

做法 A：压缩后再放

用 PyMuPDF 重压内嵌插图（文字层保留）：


import pymupdf
d = pymupdf.open("原书.pdf")
d.rewrite_images(dpi_threshold=150, dpi_target=120, quality=75)
d.subset_fonts()
d.save("压后.pdf", garbage=4, deflate=True, clean=True)

实测 417 MB → 88 MB（4.7 倍），标题正文二维码都清晰，只有插图略柔和。

做法 B（推荐）：拆到独立仓库

再建一个仓库专门放 PDF，开它自己的 Pages，等于再拿一份 1 GB 额度，主站不受影响。

页面里用绝对地址引用即可：


var PDFBASE = "https://<你的用户名>.github.io/<pdf仓库名>/pdf/";

本项目里对应 index.html 的 PDFBASE 和 web/shrink_pdf.py、web/push_pdf.py 两个脚本。

六、隐私红线（不可协商）

如果你们也要收群消息，请先读这段：

群聊内容只落本机，绝不推进任何公开仓库。

具体做法：

  1. 班群消息不要放进公开站的 data/ 目录
  2. 要给人看，就放在自己的私有仓库或云函数的令牌页（各用各的云函数，别蹭别人的）
  3. 收录前必须脱敏：姓名、学号、手机号、身份证号全去掉
  4. 公开的仓库配置里加一条「红线自检」，防止手滑：
  • 本项目 网页版/.github/workflows/sync-todo.yml 里有一段示例逻辑

为什么这么严：GitHub Pages 是全网可读的，搜索引擎也会抓。

班级群里的名字+学号一旦上网，是真实事故，不是吓唬人。

七、常见的坑

现象原因怎么办
部署完还是旧版GitHub Pages 有 10 分钟 CDN 缓存等一会儿，或 URL 加 ?t=时间戳 强刷
页面空白索引没生成 / 没推上去跑 build_index.py，确认 data/index.json 在
问 AI 没反应没填 API Key设置里填三格，保存
手机上好用、电脑上不行浏览器缓存了旧 Service WorkerCtrl+F5 强刷
git push 一直失败校园网 TLS 不稳改用 node deploy.mjs（走 API 直传）
加密后改不动资料lib 是密文先 python web/decrypt_all.py 还原
侧边栏列出一堆看不懂的索引里混进了非教材侧边栏按 01_教材/ 过滤（见 buildSidebar）
